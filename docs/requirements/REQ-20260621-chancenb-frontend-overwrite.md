# REQ：覆盖迁移 chanceNB/mu 前端

## 原始需求

用户请求：“我当前的项目要他的前端”，并在确认风险后回复“允许覆盖”。

## 功能需求

1. 以 `chanceNB/main` 的 `frontend` 内容为迁移源。
2. 覆盖当前项目中的前端应用入口、路由、页面、组件、样式、类型、store 和前端测试。
3. 覆盖后保留项目后端代码不变。
4. 覆盖后保留项目文档流程记录，并创建 Evidence / Acceptance。
5. 覆盖后运行前端测试和构建，记录真实结果。

## 约束

- 不新增依赖；`chanceNB/main` 与当前项目前端依赖集一致。
- 不让前端直接调用 LLM API。
- 不在前端代码或文档中写入 API key、token、密码等敏感信息。
- 不修改后端 API 合同；如果前端引用了当前后端暂未具备的 API，只记录为后续集成风险。
- 当前工作区存在大量未提交改动，用户已允许覆盖前端；覆盖范围仍限制在 `frontend/` 与本次流程文档。

## 兼容性需求

- Vite / Vue / TypeScript 工具链应继续使用当前项目已有依赖版本。
- 如果覆盖后测试或构建失败，必须记录失败命令、失败摘要和是否由迁移源代码导致。

## 成功标准

- `cd frontend && pnpm test -- --run` 已执行。
- `cd frontend && pnpm build` 已执行。
- 验收文档给出 PASS / PARTIAL / FAIL 判定。
