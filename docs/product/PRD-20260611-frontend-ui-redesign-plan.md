# 前端 UI 修复计划 PRD

## 背景

2026-06-11 前端 UI 审查结论显示：当前前端可用于功能验收，但整体更像接口验收台或中保真原型，不像面向学生、教师、管理员的成熟学习产品。用户明确反馈“好丑”，并要求“参考别人的前端”后写修复计划。

## 目标

设计一个可执行的前端 UI 改版方案，让 AI Learning OS 从“功能堆叠页面”转为“角色任务驱动的教育 SaaS 工作台”。

## 用户与场景

| 角色 | 主要任务 | 当前痛点 | 改版目标 |
|---|---|---|---|
| 学生 | 提问、查看引用、跟随学习路径、完成测评 | 首屏信息太多，API/trace 噪音重，移动端入口下沉 | 首屏看到问题输入、回答、来源摘要和下一步学习 |
| 教师 | 审核 AI 资源、批准或退回 | 审核规则和队列信息分散，决策区不够像工作流 | 队列 + 当前资源 + 决策动作清楚 |
| 管理员 | 观察系统健康、告警、成本、模型供应商 | 假图表感强，健康/告警优先级不清 | 以异常 triage 和真实状态为中心 |

## 产品原则

- 中文产品体验优先；英文 API path、状态枚举、traceId 放诊断层。
- 主任务优先；证据链可见但不抢主视觉。
- 管理端可信度优先，不用看似真实的假图。
- 移动端首屏必须可直接进入核心任务。
- 保留现有后端/API 边界，不扩大成后端改造。

## 非目标

- 不新增后端接口。
- 不新增数据库字段。
- 不引入新 UI 组件库。
- 不复制 GitHub 项目代码。
- 不实现真实生产图表后端指标。
- 不改变权限、RAG、Agent、Review Gate 业务语义。

## 成功标准

- `pnpm build` 通过。
- 现有前端测试通过，并新增/调整 UI 结构测试。
- 桌面截图中三类角色首屏各有明确主任务。
- 移动端学生首屏能看到核心提问入口或主操作。
- API path、traceId、状态展示示例不再占据主任务视觉中心。
